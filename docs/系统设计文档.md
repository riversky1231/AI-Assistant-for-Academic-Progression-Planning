# B 组后端设计文档

## 1. 技术架构

```text
Controller -> Service -> Mapper/MyBatis-Plus -> MySQL
                     -> Redis Cache
Redis Token Interceptor -> DB-backed roles/permissions
AgentController -> AgentConversationService -> AgentService -> LlmClient -> Chat Completions API
                                          -> Redis         -> SchoolService / RecommendationService
                                                           -> SkillLoader
```

工程采用 Controller、Service 接口、ServiceImpl、Mapper、Entity、DTO、VO 分层。Controller 只处理 HTTP 契约，ServiceImpl 实现业务规则，Mapper 负责参数化 SQL，Entity 对应数据库表，DTO/VO 隔离输入输出。

## 2. 数据模型

- `school`：学校基本信息。
- `major`：专业，外键指向学校，学校与专业名唯一。
- `admission`：学校、专业、生源省份、科类、年份、最低分和最低位次。
- `sys_user/sys_role/sys_permission`：用户、角色、权限；用户资料包含昵称、手机号、邮箱和微信 openid 绑定字段。
- `sys_user_role/sys_role_permission`：多对多权限关系。

`major` 建立 `(id, school_id)` 唯一键；`admission` 使用 `(major_id, school_id)` 复合外键，数据库层面阻止“厦门大学 + 福州大学专业”这类错误组合。

## 3. 推荐算法

```text
gap = 历史最低位次 - 用户位次

gap < -2000  -> 冲
-2000..2000  -> 稳
gap > 2000   -> 保
```

同类别按 `abs(gap)` 从小到大排序，每类最多返回 5 条。只取同一学校、专业、省份、科类的最新年份记录。地区偏好支持“江浙沪”“长三角”和多个省市分隔输入。

## 4. 缓存设计

- 学校详情：`academic:school:{id}`，10 分钟。
- 推荐结果：`academic:recommend:{SHA-256参数摘要}`，5 分钟。
- Redis 读取或写入失败只记录警告，核心查询回退 MySQL。

## 5. 安全设计

- 自定义拦截器从 Redis 校验随机 Token，登录、注册、微信登录、找回密码、健康检查和 Swagger 放行。
- 资料维护、改密码、退出和当前用户信息需要登录；学校接口需要 `school:read`，推荐接口需要 `recommend:use`，账号管理接口需要 `account:manage`。
- 权限码通过数据库关联查询，不在 Java 中按用户名硬编码。
- 登录用户名先做 SHA-256 摘要作为 Redis 限流键，5 分钟最多尝试 10 次。
- 找回密码要求用户名与已绑定手机号或邮箱匹配，并做 10 分钟 5 次的 Redis 限流。
- PBKDF2-HMAC-SHA256 使用随机盐和 120000 次迭代。
- 所有查询使用 MyBatis `#{}` 参数绑定；统一异常响应不暴露 SQL、堆栈或密码。

## 6. Agent 与模型接入

`POST /agent/chat` 复用登录鉴权和 `recommend:use` 权限。Agent 使用白名单工具执行查询，学校工具再次验证 `school:read`。服务端校验模型生成的参数，不信任模型提供的权限或 SQL。

`LlmClient` 隔离模型协议，当前实现使用 Java HTTP Client 调用兼容 Chat Completions 的服务。通过环境变量配置开关、地址、模型、密钥和超时。工具定义在 `agent-tools.json`，工具结果回传模型生成解释，同时通过 `sources` 返回原始数据。保留供应商返回的 assistant 字段以支持工具续轮。

单次问答最多 4 轮模型请求、6 次工具调用，不支持流式响应。推荐分类仍由原规则服务决定。模型未配置、上游失败和超时分别返回 503、502、504，错误响应不含上游正文。上线前需使用目标服务商验证工具调用支持情况。

`AgentConversationService` 在 Redis 保存按用户 ID 与会话 UUID 隔离的最近最多 8 轮文本问答，TTL 30 分钟，成功完成后写入。工具中间消息不跨请求保存，以避免裁剪破坏工具协议；学校和录取事实要求重新查询。会话不存在返回 404，模型失败保留原历史。

每用户每分钟最多 10 次请求，通过 Redis Lua 原子计数与设置 TTL。同一用户使用 `SET NX EX` 租约限制并发；释放时通过 Lua 比较所有者，避免删除别的请求持有的租约。租约 10 分钟，模型每轮超时最多 60 秒。限流返回 429，并发冲突返回 409。

会话保存通过 `setIfLockOwner` 将租约所有者检查与历史写入放在同一 Redis Lua 操作中，避免锁检查后过期导致旧请求覆盖新历史。失去租约的请求返回 409，不写入本轮结果。

`SkillLoader` 启动时加载打包的张雪峰视角适配入口和资料白名单，每轮固定注入入口，模型按需调用 `read_skill_resource` 读取背景研究。`data.skill` 返回指令哈希、注入状态和本轮读取路径；它证明上下文传入，不保证模型遵循全部规则。当前没有联网搜索和强制咨询流程状态机。

接口联调契约见 [Agent 接口文档](Agent接口文档.md)，提交前检查结果见 [LLM 与 Agent 模块检查](LLM-Agent模块检查.md)。
