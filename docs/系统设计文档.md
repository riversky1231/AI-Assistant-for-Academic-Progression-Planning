# B 组后端设计文档

## 1. 技术架构

```text
Controller -> Service -> Mapper/MyBatis-Plus -> MySQL
                     -> Redis Cache
Redis Token Interceptor -> DB-backed roles/permissions
```

工程采用 Controller、Service 接口、ServiceImpl、Mapper、Entity、DTO、VO 分层。Controller 只处理 HTTP 契约，ServiceImpl 实现业务规则，Mapper 负责参数化 SQL，Entity 对应数据库表，DTO/VO 隔离输入输出。

## 2. 数据模型

- `school`：学校基本信息。
- `major`：专业，外键指向学校，学校与专业名唯一。
- `admission`：学校、专业、生源省份、科类、年份、最低分和最低位次。
- `sys_user/sys_role/sys_permission`：用户、角色、权限。
- `sys_user_role/sys_role_permission`：多对多权限关系。

`major` 建立 `(id, school_id)` 唯一键；`admission` 使用 `(major_id, school_id)` 复合外键，数据库层面阻止“厦门大学 + 福州大学专业”这类错误组合。

## 3. 推荐算法

```text
gap = 历史最低位次 - 用户位次

gap < -2000  -> 冲
-2000..2000  -> 稳
gap > 2000   -> 保
```

同类别按 `abs(gap)` 从小到大排序，每类最多返回 5 条。只取同一学校、专业、省份、科类的最新年份记录。地区偏好支持“江浙沪”“长三角”和多个省市分隔输入。

## 4. 缓存设计

- 学校详情：`academic:school:{id}`，10 分钟。
- 推荐结果：`academic:recommend:{SHA-256参数摘要}`，5 分钟。
- Redis 读取或写入失败只记录警告，核心查询回退 MySQL。

## 5. 安全设计

- 自定义拦截器从 Redis 校验随机 Token，登录、健康检查和 Swagger 放行。
- 学校接口需要 `school:read`，推荐接口需要 `recommend:use`。
- 权限码通过数据库关联查询，不在 Java 中按用户名硬编码。
- 登录用户名先做 SHA-256 摘要作为 Redis 限流键，5 分钟最多尝试 10 次。
- PBKDF2-HMAC-SHA256 使用随机盐和 120000 次迭代。
- 所有查询使用 MyBatis `#{}` 参数绑定；统一异常响应不暴露 SQL、堆栈或密码。
